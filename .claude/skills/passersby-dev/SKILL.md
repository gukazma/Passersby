## 2. 画风（11-27 定：样张 A + 更细像素）

- 参考的是用户给的那类精致 3/4 像素游戏的**品质**，不照搬任何现成游戏的画面或素材。
- 原生分辨率 **960×540**，游戏里 ×2 显示，只用整数倍、最近邻。AI 出图时每个美术像素约 3.2 个图像像素，出图尺寸 3072×1728。
- 线条和配色：
  - 每个物体都有干净的深色描边；
  - 平涂，每种材质 2–3 个色阶；
  - 不要噪点、抖动、模糊、渐变；
  - 暖色调，阴影也是暖色。
  - 界面不用蓝紫。人物衣服可以用牛仔蓝等颜色，这条只限 UI。
- 比例：人大约是两层店铺高度的 1/4，主角原生身高约 110 px。门高约为人高的 1.3 倍，桌面到腰，凳面到膝。室内外要用同一套比例（见 §5）。
- **招牌字由 AI 直接写在原图上**：对像素化之前的 AI 原图做编辑，用短提示词把店名写上去。11-27 用户否掉了「像素字体后贴」：「字被遮掉了一半，和牌匾融合，字都很奇怪，为啥不能直接生成」。
  - 每块招牌出 2 版。像素化后放大 2 倍逐字读，有错字、漏字、改了板色、带光晕的版本淘汰。
  - 用 `scripts/env/drift.py` 检查排版有没有跑位，跑位了就重新量门的坐标。
  - 小牌子（路名牌等）AI 写不清：在原图上先画一块更大的牌，再用黑体加描边写字（`scripts/env/plate_raw.py`、`scripts/signbake_raw.py`），然后整体像素化。字在像素化后至少要约 20 px 高才认得出。
  - 绝不在像素化之后再贴字。
- 被否掉的做法，不要再用：
  - 像素字体烘焙或贴字的招牌（字小、发虚、像被遮了一半）；
  - 超细像素的正立面整排楼：缩小后发糊；
  - 楼顶露得很多的俯视城市；
  - 加粗的招牌字：会糊成一团。

## 3. 出图 → 真像素

- **提示词要短**。用户 11-27 指出提示词可能太详细；做了 A/B 测试：同一个任务，短提示词约 70 词、长提示词约 190 词，各出 3 版，效果一样，短的还略好。依据是 OpenAI 的出图指南：给每张参考图标号并说明用途，按「场景 → 主体 → 细节 → 限制」写。
  - 写法：「Image 1: <用途>. Image 2: <用途>. Draw <内容>, same positions/size, same pixel art style as Image N. Flat magenta #FF00FF background. No text, no shadow.」
  - 不写像素尺寸数字，也不写长串规则。比例靠灰色 1.7 m 比例人加 `--fit` 来定，场景见 `references/env_notes.md`。
  - 一张图引用两张参考图（角色 + 板凳）时，容易出成黑底发光，约一半要淘汰。坐姿只画人，提示词写「Draw only the man, not the bench」。
  - 半透明的东西（烟、残影）会和洋红混成粉色，交给游戏用粒子做。

1. 出图规格写成 json：`[{id,size,quality,refs,prompt}]`。
2. 在 114 上运行 `D:\games\pixel_city\run_teamo_114.cmd <spec> <workdir> <并发>`。key 由脚本从 114 的用户环境变量读取，绝不回显。
3. 整张场景用 `python tools/scene/pxscene.py art/x.png out/x --colors 64 --autosigns texts.json --show 1`，流程是：
   - 检测像素网格；
   - 每个像素块取众数色；
   - K-means 统一调色板；
   - 去掉孤立像素；
   - 找到空白招牌并烘焙文字。
   - 要固定像素尺寸时加 `--pixel P`。室内图要用这个参数把比例对到 §5。
4. 精灵和单个物件：洋红底，用 `tools/art/pixelize.py` 处理（见 pixel-sprite-anim skill）。
5. 出图之后一定逐张看缩略图，再用 ×2 放大的局部检查字、描边、比例。

## 4. 人物与动画

- 主角设定稿三套（A 芥黄风衣双肩包 / B 牛仔外套托特包 / C 红开衫眼镜邮差包），每套男女两版：
  - 原稿在 `art/characters/hero{A,B,C}*.png`；
  - 用户还没选；演示先用 A 男版。
- **动作帧一律先画姿势模特，再让 AI 照着画**。原因：AI 画侧面走路不可靠，用户 11-27 连续指出两次：先是同手同脚，然后是一侧长出两只手臂。
  - 用 `scripts/poseguide.py` 程序画 8 帧灰色模特：
    - 关节角取自正常步态常模（Perry / Winter），见 `references/gait.md`；
    - 浅灰是近侧肢体，深灰是远侧肢体；
    - 脚跟着小腿一起转。上一版脚始终保持水平，结果折叠到小腿上，用户说「脚折叠得太窄」。
  - 出图时引用两张参考图：图 1 姿势模特，图 2 角色设定稿。提示词里写明：只有两只手两条腿；远侧手臂藏在躯干后面，只露手；摆臂和同侧腿反向。
  - 根运动直接用模特的设计值：两帧都踩在地上的脚点算出的后移量，走路每帧约 ±5% 均匀。不再从 AI 图里测。
  - 出图后逐帧检查：手臂数量、交叉摆臂、脚的朝向；轮廓要和模特对得上。
- **每个人走路都不一样**（用户 11-27 强调，「这个细节务必抓住」）。每个角色写一份步态档案（`scripts/gait_profiles.json`），poseguide 加 `--profile` 后按档案画出不同的模特，AI 再照着画：

  | 参数 | 含义 |
  |---|---|
  | height_m / leg_len / head / torso / girth | 身高、腿长、头身比、躯干长、胖瘦 |
  | stride | 步幅 |
  | knee_load / knee_swing / ankle | 承重屈膝、抬脚高度、踝的幅度 |
  | lean / stoop / head_fwd | 前倾、驼背、头前伸 |
  | arm_swing / elbow / arm_mode | 摆臂幅度、肘屈；swing / behind_back / bag_near / pockets |
  | fps | 步频 |

  现有档案：

  | 档案 | 步态特点 |
  |---|---|
  | 主角 | 普通放松 |
  | 老人 | 微驼、头前伸、步小、抬脚低、背着手、9 fps |
  | 健身 | 挺胸、大步、屈肘有力摆臂、13 fps |
  | 胖 | 后仰、步小、摆臂小、腿短、10 fps |
  | 买菜主妇 | 近侧手拎袋不摆 |
  | 小学生 | 头大腿短、蹦、15 fps |
  | 上班族 | 直腰、插兜 |

  新角色先按年龄、体型、职业、性格选一个最接近的档案改参数。速度 = 根运动 × 步频，所以每个人的速度也自然不同。
- **角色动画流水线**（脚本都在 `scripts/`）：
  1. 设定稿：男女各一行，正面、侧面、背面、走姿各一张，用 3072×1536。
  2. 侧面走：
     - `poseguide.py <guide.png> <guide.json> --profile <档案>` 生成 8 帧朝右的模特，格子 384×1024；
     - 出图规格引用两张参考图：模特和设定稿；尺寸 3072×1024；每个动作出 3–6 版。
  3. 正面、背面走：用 `poseguide_fb.py --view front|back`。投影系数：地面 0.4，竖直 0.92。根运动沿 y 轴。
  3b. **斜走**（11-27 用户要求）：用 `poseguide_yaw.py --yaw 45`（右前斜，3/4 正面）或 `--yaw -45`（右后斜，3/4 背面），朝左用镜像。参考做法是 8 方向精灵：先画 5 个方向，再镜像出 3 个。
     - json 里 axis 写 dir，同时写 dir_screen = [cos, sin×0.4]。游戏里每帧的位移 = 根运动 × dir_screen。
     - 测不准时（脚在画面上高低交替）改用模特的设计值。
     - 动画名：walk_diagf、walk_diagb。
  4. `walkbuild.py <ai.png> <guide.json> out/<名>` 依次完成：
     - 转成真像素，身高固定（主角 110 px）；
     - 按帧与帧之间的空隙切帧，不能等分，等分会切掉脚尖；
     - 去掉洋红杂边；
     - 按上半身质心对齐；
     - 测量着地脚的位移，作为根运动，并向平均值收拢 50%；
     - 回放计算脚滑。
  5. 挑版本：先看画面，没有虚影、没有多出的手、脚没被切；再看数字，`slip_mean_px` ≤ 1.5 才算好。
     - 11-27 主角侧走选了 f 版：slip 1.35，速度约 80 px/s，fps 10。
     - 剔除过的问题：黑底、腿上沾了模特的灰色、半透明手臂。
- 横版只需要画朝右的帧，朝左用镜像。所以服装尽量做成左右对称：不要单侧 logo，包和伞镜像之后也要看着合理。
- 每个角色都要有这些帧：
  - 站立：正侧面、双脚着地、有呼吸起伏；
  - 走 8 帧、跑 8 帧；
  - 正面（对话、待机）；
  - 背面（进门、看橱窗）；
  - 转身。
- 走和跑都用 F 根运动：身体每帧前进的距离 = 实测着地那只脚的位移。速度由步幅算出来，不能拍脑袋。
- 腿不要用程序直接画成成品：A1.2 那样画出来的跑步，用户说「姿势好怪」。程序只负责画姿势模特，衣服和形体交给 AI。

## 4b. 动作与互动（11-27 用户要求：坐下、和道具互动、抽烟、逗狗、拍照、开心大笑……「动作不只是行走」）

- 动作帧用短提示词，以角色设定稿作参考出图，再用 `specbuild.py` 按下半身对齐，离地动作加 `--anchor none`。json 字段：
  - `loop`、`view`；
  - `seat_point`：坐姿精灵里只画人，人放在家具前面，用这个点对准座面中心；
  - `hand_point`：摸狗时狗头的位置；
  - `smoke_frame` 和 `mouth_point`：游戏在这一帧、从嘴边冒出灰色像素烟；
  - `shutter_frame`：拍照时在这一帧截图并闪白。
- 已有的动作：
  - 主角：sit_bench（正面坐长椅）、photo、laugh、pet_dog；
  - 罗伯：sit_tea；
  - 叶永和：smoke、sit_stool；
  - 黄丽：laugh；
  - 乐乐：pet_dog、jump；
  - 叶俊：phone；
  - 狗旺财：walk_side、run_side（快步）、idle_side、sit、happy。狗的姿势模特用 `scripts/actions/dogguide.py`，四拍步态，步幅约 1.0 倍肩高。
- world.json 里的配置：
  - `spots`：座位，写坐标、朝向、NPC 用的动画、主角用的动画；
  - `extra_props`：补摆的家具，场景美术重做时不会被覆盖；
  - NPC 的 loop 指令：`["use", 座位, 秒, 动画]`、`["anim", 动作, 秒]`、`["pet", "wangcai", 秒]`；
  - 对话行可以写成 `{"t": 台词, "anim": "laugh", "hero": "laugh"}`，说到这句时 NPC 和主角一起笑。
- 主角按空格的优先顺序：说话 > 摸狗 > 坐下 > 进门 > 过马路。坐着时按空格或方向键起身。按 P 是主角举手机拍照。

## 4c. BGM（11-27 用户要「星露谷那种温馨风格」：只取风格，曲子原创）

- 用豆包语音 seed-audio-1.0 生成，key 是 114 `.env` 里的 VOLC_TTS_APIKEY_NEW；脚本 `scripts/seed_bgm.py`，规格见 `scripts/seed_spec.json`。中文提示词写清：纯音乐、乐器、BPM、场景、可循环。每首最长 120 秒。
- Suno 的 key 返回 401，ElevenLabs、MiniMax、fal 都没配 key。
- 生成后的处理：
  - 结尾 3 秒和开头交叉淡化，做成无缝循环：`atrim 3:120` 接 `atrim 0:3`，用 `acrossfade`；
  - 用 loudnorm 统一响度到 −18 LUFS，转成 ogg，放进 `side_data/bgm/`；
  - world.json 的 `bgm` 写每个场景对应哪首，换场景时淡入淡出。
- 用频谱图检查：有和声和节拍、没有人声、没有长时间静音。

## 5. 横版玩法（11-27 定，类似蜡笔小新横版游戏的移动方式）

见 `references/side_scroll_design.md`。纵向（W/S）走用正面和背面行走帧，不能用侧面帧平移。参考：《蜡笔小新 我与博士的暑假》是固定视角加手绘背景，角色能在画面里往纵深方向走：街道是横条、人行道是纵深带、在路口转弯、过马路走斑马线、进门、室内、NPC 的日程和交互。

## 7. 演示录制与讲解视频（A1.3 做法）

- **自动演示**：`side_data/clip_*.json`，启动参数加 `-- --demo=clip_x.json --quit_after_demo`。可用的指令：
  - 移动：`{x,y,run,t}`；
  - `walkto`、`approach`（走到某个 NPC 身边）、`interact`、`talk`（自动翻页）；
  - `down`（过马路）、`take_photo`、`stand`、`wait`。
  - `time`（"HH:MM"）、`fast`（时间快进开关）、`zoom`（`{"act":"zoom","v":2,"dy":-45}`，只在演示里放大镜头，中心 = 主角脚下 + dy；用整数倍 2，像素才不变形）。
  - A1.5 起讲解视频的细节镜头（影子、脚、鸽子、猫狗）一律用 `zoom` 2 倍录，原比例下人影、鸽子太小，手机上看不出来。
  - 室内要沿通道走（先沿下沿，再往里，再横着走），否则会被桌凳卡住。
- **录制**：在实验机上用 Movie Maker 录，参数 `--write-movie x.avi --fixed-fps 25 --rendering-driver d3d12`。
  - 录出来的是 960×540，合成时用 `scale=1920:1080:flags=neighbor` 放大。
  - AVI 带游戏原声（BGM），可以直接当背景声。
- **搬运**：实验机和 114 之间用 `scp -3 -F 临时 ssh 配置`，两台机器各写一个 Host。不能共用 ControlPath，否则会连到同一台机器上。
- **视频合成**：在 114 上用 `tools/video/build_video.py`：
  - 旁白用 edge-tts Yunxi +4%；
  - 说话时用 sidechain 压低背景；
  - 字幕带半透明底板，不然会压在静态画面的内容上；
  - 片头封面 3 秒；
  - 整片 −16 LUFS。
  - 讲解静态画面由 `stills.py` 生成。
- **A1.5 讲解视频的做法**（`tools/video/a15/`）：游戏片段 `side_data/w_*.json`（用 `zoom` 放大细节）；旧/新对比片段 `cmpclips.py` 直接从精灵表渲染（旧版从 git 历史或 backup 取，标出「离地 N 像素」）；`grab.py` 按时间点抽帧拼图逐段核对画面和旁白是否对得上；`--trace_demo` 打印演示中主角每 0.5 秒的位置和动画（查「为什么没被挡住」这类问题）。
  - 自己渲染的对比片段放进 AVI 时用 MJPEG（`-c:v mjpeg -q:v 2 -r 25`），不要把 H.264 拷进 AVI：时间戳会乱，成片里 4 秒后就定格（A1.5 v1 第一次合成踩过，qc 的冻结检查抓到的）。
  - 字幕在底部约 150 px：对比图、总结卡的内容都要避开这块。
  - 演示脚本只拍真实发生的事：旁白说「迎面让开」，画面里就得有；拍不到就删掉这句。
- **交付前检查**：`qc.py` 测响度和峰值，扫描冻结和静音，再抽帧看一遍。成品放 `D:\Lumo视频\我亦是行人\`，用 `--list` 确认归类正确。

## 8. 测试规范（11-27 用户：「做好严格测试，避免简单的 bug」「查查别人自动化测试和美术视觉测试怎么做」）

每次交付（给用户试玩、录视频、推送）之前必须全部通过，失败就不交：

1. **素材检查** `game/tests/lint_assets.py`（沙盒就能跑）：
   - 道具被直线切掉、洋红杂边；
   - 动画帧尺寸、脚底一致、头顶或边缘被切；
   - 侧走触地帧两只脚大小相近（防「外卖员一只脚被切掉」）；
   - 速度范围、根运动负值；
   - 头像齐全；
   - world.json 引用、座位附近有长椅、NPC 路点不在家具里、补摆道具不挡门、台词长度。
2. **一键全套** `game/tests/run_tests.cmd <godot.exe> [浸泡秒]`（实验机）：
   - 导入资源；
   - 逐个脚本做语法检查，有 Parse Error 就停；
   - 机器人测试（`--autotest`）：
     - NPC 浸泡：不能卡住、原地踏步、出纵深带、站进家具；
     - 主角三条线扫街：中线不许被挡；
     - 每扇门进出、斑马线来回、出口、每个座位、摸狗、和每个人说完话、对话头像和行数、拍照；
     - 提示牌居中且在人物头顶上方；
     - 室内走不出房间；
     - 脚步声、昼夜灯光和影子、车流不追尾、斑马线有人时车停、鸽子惊飞后再落回人行道。
3. **固定机位截图** `--shots=<目录>`：
   - 每条街每 700 px 一张，加每个人的每句对话、每个座位、门前提示；
   - 拼成接触表，我逐张看：字、裁切、重叠、比例；
   - 角色动画另外看 x3 总表。
- 视觉检查参考：基准截图对比（视觉回归）、VideoGameQA-Bench 用视觉模型找穿模和 UI 问题、gdUnit4 SceneRunner 模拟输入。
- 坑：
  - GDScript 的 `:=` 碰到 Dictionary/Variant 值推断不出类型，会让整个脚本 Parse Error，要显式写类型；
  - 补摆的 `res://` 图要先 `--import`；
  - tween 绑定在会被释放的节点上（`l.create_tween()`），否则换场景后回调访问已释放的对象；
  - 实验机上的旧 Godot 进程会锁住日志，跑之前先 `taskkill`；
  - 远程会话截图只有 960×540。
- AI 出图守门（walkbuild）：
  - 原图背景不是洋红（黑底、发光底）的直接淘汰；
  - 每帧脚底对齐到同一底线；
  - 触地帧脚大小检查。

## 9. 街道生活（A1.4）

- `game/side/ambient.gd` 每个场景 setup 一次、每帧 tick：
  - **时间**：默认 16:00，2 游戏分钟 / 秒，T 键 12 倍快进；
  - **CanvasModulate 调色**：晨、昼、黄昏、夜；
  - **影子**：楼排和高道具的剪影翻到地面上压扁，随太阳倾斜和伸长，日落后淡出；
  - **灯光**：路灯（有一盏会闪）和每扇门的店灯用 PointLight2D，夜晚才亮；车灯坐标在 vehicles.json；
  - **粒子**：树下落叶、锅和蒸笼的蒸汽，都随风；风速缓慢变化；
  - **车流**：近车道向左、远车道向右，不追尾，有人在斑马线上就停，经过镜头时放过车声；
  - **鸟群**：鸽子和麻雀在地上，人、车靠近就惊飞，在天上绕圈后落回人行道；海鸥在天上盘旋；
  - **定位音效**：AudioStreamPlayer2D 池，近大远小；
    - 脚步按 sfx.json 的 `_shoe_map` 区分鞋子，室内运动鞋换成瓷砖声，在落脚帧（0 和半周期）触发；
    - 环境声按场景切换。
- world.json 新增：
  - `fx`：蒸汽位置；
  - `fauna`：鸟群类型、位置、数量、在地上还是天上；
  - 猫狗当作 NPC 写进 npcs，用 loop/special。
- 素材笔记（来自各分工流程）：`references/{portraits,animals,vehicles,sfx,env,actions,npc}_notes.md`。
- 步态第二版（用户说「像踢正步」「跑起来人没跑起来」）：
  - 髋角减骨盆前倾 10°（tilt），大腿不再整体前甩；
  - 主角走路 stride 1.3、7.5–8.5 fps，跑步 stride 1.35、11 fps，约 2.7 m/s；
  - NPC stride ×1.2–1.25，步频降到 6.5–10.5。

## 10. A1.5 规则（11-27 用户试玩 A1.4 后）

- **界面要干净**：平时屏幕上不放任何文字——不要头顶按键提示、操作说明栏、地名、时钟、转场大字、随机情绪气泡。只有对话框（头像 + 名字 + 爱心 + 台词 + 一个 ▼）。玩家靠走近按空格交互。autotest 的 ui 段断言平时 HUD 里没有可见 Label。
- **原图里不能画会动的东西**：蒸汽、烟、火、水花这类由游戏做粒子；AI 场景图/道具图里画了的要抠掉（面馆立面 `row_yn_block1` 的锅上蒸汽按行补底色；陈记 `counter.png` 锅上的蒸汽直接去掉，锅口补成深色）。出图提示词加「no steam, no smoke」。
- **粒子放对位置、参与遮挡**：fx 写锅口坐标 + `depth`（锅所在的纵深，店里的锅 = 楼脚 391），蒸汽节点放进 ysort，路过的人挡在蒸汽前面。
- **太阳影子**（ambient.gd `_update_sun` / `_sync_shadow`）：镜头朝南，影子朝镜头落；横向 ax = −方位 × cot(高度角)，纵向 ay = cos(方位) × cot × 0.45；早上斜向右、中午短、傍晚斜向左且长，日落前淡出。角色、车、地上的鸟每帧复制当前帧做剪影影子；楼排按 0.35 倍只压一条随屋顶起伏的阴影；所有影子画进一个 CanvasGroup，重叠不叠黑。脚下的小椭圆接触阴影保留。
- **脚要贴地**：侧面走/跑/站每一帧的最低点都在 origin y 上（跑步按姿势模特每帧都有一只脚着地，不做腾空帧）。walkbuild 之后跑 `scripts/snapfeet.py <char_dir> <anim>`；lint `[悬空]` 不过不交。
- **碰撞不抽风**（actor.gd `drive`）：先按意图选动画、算根运动、做碰撞；有分量被挡就换成和实际位移一致的动画（斜走贴墙 → 侧走；横向挡住 → 正/背面走；横走撞到人 → 用正/背面帧让一步）；完全走不动就站住并保持 0.15 s，不在走/站之间每帧来回切。autotest `collide` 段断言动画切换 ≤ 3 次、动画方向和位移一致。
- **人和猫狗互不阻挡**（actor `kind`）：猫狗小，人从旁边走过去；autotest `live_sweep` 带着全部居民和动物扫街，卡住不能超过 1.5 秒。
- **鸟的行为**（ambient.gd `BIRD` 表）：城市鸟习惯了车和行人——车不惊鸟；行人走近（鸽子 75 px）只是走开；贴近 34 px、有人跑近 120 px、猫狗冲过来 110 px 才整群惊飞；陡升 → 鸽子绕一圈（约 4 s）→ 60% 落屋脊（从楼排图找平的屋脊）、40% 落远处没人的地面 → 屋脊上歇 10–25 s，觅食点没人再飞回地上。麻雀直接躲屋脊、5–12 s 回来；海鸥借风盘旋。每只鸟 = 地面点 (x, 纵深) + 高度 alt，节点在 ysort 里按地面点排序、精灵向上抬 alt，所以会被树、路灯、行人挡住；落屋脊的纵深 = 楼脚。autotest `birds` 段：站远处 40 秒鸽子在天上 < 10 秒、走近先走开、跑近惊飞、15 秒内落下、60 秒内回到地上。

- **NPC「卡住」按有没有接近目标算**（npc.gd `walk_to`）：在障碍物角上「往下让一步 → 离目标纵深超过 1.5 px → 又往上走」会无限上下抖，人在动所以旧的「没动才算卡」永远不触发——这就是用户说的「抽风」。现在 0.4 秒没接近目标就用 `_pick_detour` 往前看 24 px、找上下能过去的一侧绕行。
- **只有人挡人**：猫狗不挡人、人也不挡猫狗、猫狗之间也不互挡（两只动物在窄处互相等会卡死）。
- **测试不能卡死**：每个循环都要有时间上限；run_tests.cmd 加 `--quit-after 108000`（30 分钟）兜底，没有 RESULT 行就算失败。调试时 `-- --autotest --only=soak+collide --trace_npc=<cid>` 只跑某几段并打印某个 NPC 的轨迹（cmd 里逗号会被当成参数分隔，用 + 连接）；交付前必须全跑。
- **测试自己的摆位也要避开家具**：「迎面撞人」测试先找两边都空的位置再摆人，否则主角会被放进水果摊的碰撞框里（假失败）。

- **录视频本身就是一次视觉验收**（11-28）：A1.5 录影子片段时才发现人的投影太淡（不透明度 0.34，autotest 只断言了变换矩阵、没看清浓淡），下午人站进楼影里还会和楼影融成一片。已把浓度提成可调的 `SHADOW_ALPHA`（0.46）。以后改视觉效果，交付前要按游戏原比例截一张图看清楚，不能只看断言。
